# Folder Structure

Annotated breakdown of every significant directory and file in the monorepo.

```
.
├── apps/
│   ├── api/                        # Express 5 backend
│   ├── web/                        # React 19 frontend
│   └── design-system/              # Storybook component catalogue
├── packages/
│   ├── ui/                         # Shared React component library
│   ├── schemas/                    # Shared Zod schemas and TypeScript types
│   ├── eslint-config/              # Shared ESLint rules
│   ├── prettier-config/            # Shared Prettier rules
│   ├── tailwind-config/            # Shared Tailwind base CSS
│   ├── typescript-config/          # Shared tsconfig presets
│   └── vitest-config/              # Shared Vitest presets
├── scripts/
│   └── setup.mjs                   # One-time project initialisation
├── docker-compose.yml              # Dev service orchestration
├── package.json                    # Root package (husky, setup script)
└── pnpm-workspace.yaml             # Declares apps/* and packages/*
```

## `apps/api/`

The Express API. All source lives under `src/`; the `prisma/` directory holds the database schema and generated migrations.

```
apps/api/
├── prisma/
│   ├── schema.prisma               # Single User model; PostgreSQL datasource
│   └── migrations/                 # Auto-generated by `prisma migrate dev`
├── src/
│   ├── index.ts                    # App bootstrap: middleware stack, session, router mount
│   ├── routes/
│   │   ├── index.ts                # Root router: mounts /auth and /users sub-routers;
│   │   │                           # contains the 404 handler and global error handler
│   │   ├── auth.ts                 # POST /login, POST /logout, GET /session
│   │   └── users.ts                # POST /, GET /me, PUT /:id, PATCH /:id/password,
│   │                               # DELETE /:id
│   ├── controllers/
│   │   ├── auth.controllers.ts     # Thin request/response layer for auth routes
│   │   └── users.controllers.ts    # Thin request/response layer for user routes
│   ├── services/
│   │   ├── auth.services.ts        # loginUser: lookup + bcrypt compare
│   │   └── users.services.ts       # createUser, fetchUser, updateUser,
│   │                               # updateUserPassword, deleteUser
│   ├── middleware/
│   │   ├── auth.ts                 # addAuthMiddleware: checks for session cookie and
│   │   │                           # req.session.user; returns 401 if absent
│   │   └── validate.ts             # Zod request body validation; returns 400 on failure
│   └── lib/
│       ├── db.ts                   # Singleton PrismaClient (PrismaPg driver)
│       └── prismaError.ts          # Maps Prisma known errors to http-errors status codes
├── prisma.config.ts                # Prisma config (schema path + DATABASE_URL)
├── custom.d.ts                     # Empty Express namespace augmentation (placeholder)
├── nodemon.json                    # Watches src/ for changes in dev
├── Dockerfile.dev                  # Dev image: Node 20 Alpine, pnpm, nodemon
├── .env.sample                     # Required env vars: DATABASE_URL, ACCESS_TOKEN_SECRET,
│                                   # CORS_ORIGIN, COOKIE_DOMAIN, API_PORT
└── package.json                    # @template/api — scripts, deps
```

```
│   │                               # RouterProvider

│   │   ├── query.ts                # Singleton QueryClient
│   │   ├── utils.ts                # cn() helper (clsx + tailwind-merge)
│   │   └── index.ts                # Re-exports router and queryClient
│   ├── routes/
│   │   ├── __root.tsx              # Root route: wraps all routes in MainLayout;
│   │   │                           # includes devtools (router + query)
│   │   ├── index.tsx               # Route "/": Welcome placeholder
│   │   └── _auth/
│   │       ├── login.tsx           # Route "/_auth/login": renders LoginView
│   │       └── registration.tsx    # Route "/_auth/registration": renders RegistrationView
│   ├── features/
│   │   └── Auth/
│   │       ├── api/
│   │       │   └── authApi.ts      # Empty — API call stubs to be added
│   │       ├── components/
│   │       │   ├── Login/
│   │       │   │   ├── LoginContainer.tsx      # Wrapper shell
│   │       │   │   └── LoginForm.tsx           # Stub — renders placeholder div
│   │       │   └── Registration/

│   │       └── views/

│   │       └── MainLayout/         # Wraps page content below the ApplicationBar

│   └── vite-env.d.ts               # Vite client types + svgr types
```

## `packages/ui/`

Shared React component library consumed by `apps/web` and documented in `apps/design-system`. Exported as TypeScript source, not compiled.

```
packages/ui/
├── src/
│   ├── index.ts                    # Public API: re-exports everything
│   ├── components/
│   │   ├── Button/
│   │   │   └── Button.tsx          # CVA-styled button; asChild via Radix Slot
│   │   ├── Forms/
│   │   │   ├── Form/
│   │   │   │   ├── formContexts.ts # createFormHookContexts() — fieldContext, formContext
│   │   │   │   └── Form.tsx        # createFormHook() → exports useAppForm, withForm
│   │   │   ├── Input/              # Base <input> with CVA size + state variants
│   │   │   ├── Label/              # Radix Label primitive
│   │   │   ├── FieldErrors/        # Renders TanStack Form error messages
│   │   │   ├── TextField/          # Label + TextInput + FieldErrors; reads from fieldContext
│   │   │   ├── EmailField/         # Same pattern, type="email"
│   │   │   ├── PasswordField/      # Same pattern, type="password"
│   │   │   ├── DateField/          # Same pattern, type="date"
│   │   │   ├── CheckboxField/      # Radix Checkbox + Label + FieldErrors
│   │   │   └── SubmitButton/       # Button that reads canSubmit from formContext
```

## `scripts/setup.mjs`

A one-time initialisation script (`pnpm run setup`). It walks the entire file tree and replaces:

- `@template` → `@<scope>`
- `template-monorepo` → `<project>-monorepo`
- `template-postgres` → `<project>-postgres`
- database name references in `.env` files and docker-compose defaults

Then runs `pnpm install` to regenerate the lockfile.

---

## `docker-compose.yml`

Five services:

| Service             | Purpose                         | Port        |
| ------------------- | ------------------------------- | ----------- |
| `postgres`          | PostgreSQL 17 with health check | 5432        |
| `api-dev`           | Express dev server (nodemon)    | 3001 → 3000 |
| `web-dev`           | Vite dev server                 | 9000        |
| `design-system-dev` | Storybook                       | 6006        |
| `prisma-studio`     | Prisma Studio GUI               | 5555        |

All dev services mount the entire repo as a volume (`- .:/app`) with `node_modules` excluded from the bind mount, so file changes on the host immediately reflect inside the container without a rebuild.
